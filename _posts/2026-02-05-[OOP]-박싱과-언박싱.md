## 박싱 (Boxing) & 언박싱 (Unboxing)

### **1. 값 타입 & 참조 타입**

#### **값 타입 (Value Type)**
- 실제 값 자체를 저장
- 보통 **스택 영역**에 저장
- ```int```, ```double```, ```bool```, ```struct```, ```...```

#### **참조 타입 (Reference Type)**
- 값이 있는 **주소**를 저장
- 참조 타입의 객체는 **힙 영역**에 저장
- 참조 타입의 참조 변수는 스코프에 따라 다르게 저장
- ```class```, ```object```, ```string```, ```array```, ```...```

### **2. 박싱 (Boxing)**

#### **박싱이란**
- **박싱**이란 값 타입의 변수를 참조 타입으로 감싸는 것을 의미한다. (값 타입 → object)
- 값이 **힙 영역**에 복사된다.
- 자동 변환처럼 보이지만 비용이 발생한다.

#### **예시**
```csharp
// a의 값 10을 힙에 복사하고 x가 그 주소를 가리킨다.
int a = 10;
object x = a;
```

### **3. 언박싱 (Unboxing)**

#### **언박싱이란**
- **언박싱**이란 박싱된 object를 다시 값 타입으로 꺼내는 것을 의미한다. (object → 값 타입)
- 반드시 명시적 캐스팅이 필요하다.
- 자료형이 다를 경우 런타임 에러가 발생한다.

#### **예시**
```csharp
object obj = 10;		// 박싱
int y = (int) obj;		// 언박싱

object obj = 10;
long y = (long) obj;		// 자료형이 맞지 않아 런타임 에러 발생
```

### **3. 제네릭 (Generic)**
박싱과 언박싱은 힙 메모리를 할당하기 때문에 가비지 콜렉션의 부담이 증가한다.
따라서 비용을 줄이기 위해 박싱, 언박싱을 대신하여 **제네릭**을 사용한다.

**제네릭**이란 자료형을 나중에 정할 수 있는 설계 방식이다.
```List<int>```, ```List<string>``` 등과 같이 컴파일 타임에 자료형을 검사하기 때문에 상대적으로 안전하다.
또 힙 메모리 할당이 발생하지 않기 때문에 박싱, 언박싱에 비해 상대적으로 빠르고 가볍다.  

```csharp
// 제네릭을 사용하지 않는 경우
ArrayList list = new ArrayList();

list.Add(10);						// 박싱
int x = (int)list[0];		// 언박싱


// 제네릭을 사용하는 경우
List<int> list = new List<int>();

list.Add(10);
int x = list[0];  
```
