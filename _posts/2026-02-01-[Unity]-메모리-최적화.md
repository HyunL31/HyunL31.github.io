## 메모리 최적화

### **1. 오브젝트 풀링 (Object Pooling)**

#### **오브젝트 풀링이란**
미리 여러 개의 오브젝트를 만들어 놓고 필요할 때마다 꺼내서 사용하고 다시 돌려놓는 방식이다.
**Instantiate() / Destroy()** 대신 **SetActive**를 사용해 오브젝트를 활성화, 비활성화한다.
![Desktop View](/assets/img/pooling1.jpg){: w="700" h="400" }

#### **오브젝트 풀링의 필요성**
총알, 몬스터 등 자주 생성되고 삭제되는 오브젝트는 **Instantiate() / Destroy()**를 통해 처리할 수 있다.
하지만 유니티에서 **Instantiate()와 Destroy()** 연산은 비용이 많이 필요하다.
오브젝트를 사용할 때마다 메모리 할당과 해제가 발생하고 가비지 콜렉션이 발생하여 프레임 드랍의 주범이 된다.
따라서 가비지 콜렉션 실행과 프레임 드랍을 줄이기 위해 오브젝트 풀링을 사용한다.

#### **오브젝트 풀링의 구현**
유니티 내부에는 이미 오브젝트 풀링이 구현되어 있기에 바로 사용할 수 있다.

```csharp
using UnityEngine.Pool;

private ObjectPool<GameObject> pool;

void Awake()
{
	pool = new ObjectPool<GameObject>(
		createFunc,	// 오브젝트 생성 함수
		actionOnGet,	// 풀에서 오브젝트를 가져오는 함수
		actionOnRelease,	// 다시 풀로 오브젝트를 돌려놓는 함수
		actionOnDestroy,	// 오브젝트를 파괴하는 함수
		collectionCheck,	// 중복 반환 여부 
		defaultCapacity,	// 처음 생성할 오브젝트의 수
		maxSize		// 저장할 오브젝트의 최대 크기
		);
}
```

혹은 큐를 사용해 직접 구현할 수 있다.

```csharp
using System.Collections.Generic;
using UnityEngine;

public class ObjectPool : MonoBehaviour
{
    public GameObject prefab;
    public int poolSize = 10;

    private Queue<GameObject> pool = new Queue<GameObject>();

    void Awake()
    {
        for (int i = 0; i < poolSize; i++)
        {
            GameObject obj = Instantiate(prefab, transform);
            obj.SetActive(false);
            pool.Enqueue(obj);
        }
    }

    public GameObject Get()
    {
        GameObject obj = pool.Count > 0 ? pool.Dequeue() : Instantiate(prefab);
        obj.SetActive(true);
        return obj;
    }

    public void Return(GameObject obj)
    {
        obj.SetActive(false);
        pool.Enqueue(obj);
    }
}
```

### **2. 어드레서블 에셋 (Addressable Asset)**

#### **어드레서블 에셋이란**
기존의 Resources.Load()는 에셋이 모두 빌드에 포함되며 한 번 로드한 에셋이 계속 메모리에 남아있다.
**어드레서블 에셋**은 필요한 시점에만 에셋을 로드하고 사용하지 않는 에셋을 해제하여 메모리 누수를 방지할 수 있다.

이를 통해 콘텐츠 업데이트와 배포를 효율적으로 관리할 수 있다.
다만 빌드 과정이 복잡해지고 초기 로딩이 오래 걸린다는 단점이 있다.

DLC 등의 추가 콘텐츠를 어드레서블 에셋으로 관리할 수 있다.
