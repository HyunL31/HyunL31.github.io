## 렌더링 최적화

### **1. 텍스처 압축**

#### **텍스처 압축이란**
**텍스처 압축**이란 이미지의 용량을 압축하여 메모리와 GPU의 사용량 및 로딩 시간을 줄이는 것이다.

#### **텍스처 압축 원리**
텍스처를 작은 블록 단위 (주로 4 X 4 픽셀)로 나누고 각 블록의 대표 색상만 저장한 뒤 나머지 픽셀은 보간을 통해 계산한다.

#### **텍스처 압축 방식**
- **DXT / BC** : PC 및 콘솔 게임에 적합한 방식 (DXT5 / BC7)
- **ETC / ASTC** : 모바일 게임에 적합한 방식 (요즘에는 주로 ASTC를 사용)
- **PVRTC** : 주로 iOS 기기에서 사용

#### **텍스처 압축 주의점**
텍스처 압축은 색을 보간으로 계산하기 때문에 색의 경계가 뚜렷한 이미지에 사용해서는 안된다.
UI 아이콘, 텍스트, 노멀맵, 라인 아트 등에 사용하는 것을 주의해야 한다.

### **2. 스프라이트 아틀라스 (Sprite Atlas)**

#### **스프라이트 아틀라스란**
**스프라이트 아틀라스**란 여러 개의 작은 스프라이트 이미지를 하나의 큰 텍스처로 만들어 관리하는 방법이다.
이를 통해 드로우 콜을 줄이고 렌더링 성능을 향상 시킬 수 있다.

유니티에서 텍스처를 전환할 시 드로우 콜이 발생하기 때문에 하나의 큰 텍스처로 합치면 텍스처 스위칭에 소모되는 오버헤드를 줄일 수 있다.

#### **스프라이트 아틀라스 원리**
여러 개의 스프라이트 이미지를 하나의 큰 텍스처에 배치한다.
각 스프라이트는 UV 좌표를 기준으로 자신이 사용할 영역만 참조한다.

#### **스프라이트 아틀라스 주의점**
- 서로 다른 압축 방식이나 필터 설정을 가진 스프라이트들은 하나의 텍스처로 묶기 어렵다.
- 너무 큰 아틀라스는 메모리 낭비를 유발할 수 있다.
- UI용 이미지와 게임 오브젝트용 이미지는 분리하는 것이 좋다.

### **3. 배칭 (Batching)**

#### **배칭이란**
**배칭**이란 여러 개의 오브젝트를 하나의 드로우 콜로 묶어 렌더링하는 기법이다.

#### **배칭 원리**
같은 렌더링 설정 (머티리얼, 셰이더 등)을 가진 오브젝트를 하나의 드로우 콜로 묶어 GPU에게 전달한다.
GPU는 내부적으로 각 오브젝트의 정점 데이터를 처리하여 렌더링 한다.

#### **배칭의 종류**
- **정적 배칭 (Static Batching)** : 움직이지 않는 오브젝트를 대상으로 한다.
- **동적 배칭 (Dynamic Batching)** : 작은 크기의 움직이는 오브젝트를 대상으로 한다.
- **GPU Instancing** : 동일한 메쉬와 머티리얼을사용하는 여러 오브젝트를 대상으로 한다. (나무, 구름 등)

#### **배칭 최적화**
- **머티리얼 통합** : 동일한 머티리얼을 사용하여 배칭 가능성을 높인다.
- **메쉬 결합** : 여러 개의 작은 메쉬를 하나의 메쉬로 결합한다.
- **텍스처 아틀라스** : 여러 텍스처를 하나의 큰 텍스처로 결합한다.
- **LOD (Level of Detail)** : 멀리 있는 오브젝트는 디테일이 낮은 메쉬와 머티리얼을 사용한다.

### **4. 캔버스 최적화 (Canvas)**

#### **UI Canvas**
유니티에서 **UI Canvas**는 UI가 변경될 때마다 캔버스가 다시 그려진다.
따라서 잦은 UI 변경은 CPU 부하를 증가시키고 프레임 드랍을 유발한다.

#### **캔버스 최적화 방법**
- 자주 변경되는 UI를 따로 분리한다.
- CanvasGroup, LayoutGroup 등의 컴포넌트를 남용하지 않도록 한다.
- 동일한 머티리얼과 스프라이트 아틀라스를 사용한다.
