## [OZ 게임개발캠프] 23일차 (4/20)

### **1. 유니티 에디터**
- 보통 씬을 많이 나누지 않는 경우가 많다....
	- 의도치 않게 오브젝트가 삭제되고 생성되는 경우 등 위험할 수 있다.
	- 로비 - 인게임 전환 등은 상관없긴 하다.
	- 나는 모든 씬을 나눠왔는데 충격이다.
- 게임 뷰에서 해상도 대응 중요하다.
- **Perspective** : 원근 적용
- **Orthographic** : 원근 적용 안됨
- 유니티에서 게임 오브젝트를 동적 생성 (new)하는 것은 비용이 매우 크다.
	- 그래서 로딩 등에 미리 생성한다.
- 객체 스케일은 (1, 1, 1)이 좋다.

### **3. 프리팹**
- 오히려 대형 프로젝트에서는 의도치 않은 수정을 방지할 수 있도록 프리팹의 **Auto Save**를 끈다.
- `Instantiate(프리팹, 위치, 방향, 부모)`으로 동적 생성 (메모리를 할당하는 무거운 작업, 최대한 재사용 해야 한다.)
- `SetParent`로 Root 설정 (UIRoot 등)
- 유니티에서 순회는 비용이 크기 때문에 리스트 등의 자료구조를 사용하는 것이 더 효율적이다.
- 메쉬 등은 프리팹이 참조하는 형태이기에 프리팹의 용량이 늘어나지 않는다.

#### **프리팹 동적 생성 예시**
```csharp
// 실체화 후 부모 설정
var carPrefab = Instantiate(carPrefab, spawnPos, Quaternion.identity);
car.transform.SetParent(carRoot.transform);

// 스페이스 누르면 생성
if (Input.GetKeyDown(KeyCode.Space))
{
	// 실체화와 함께 부모 설정
	Instantiate(carPrefab, spawnPos.position, Quaternion.identity, carRoot.transform);
}
```

### **4. Destroy**
- 런타임에 컴포넌트를 Destory 해서는 안된다.
- `Destroy(this)`를 사용하면 스크립트 컴포넌트가 없어진다.
- Destroy는 즉시 삭제되지 않고 프레임의 모든 로직이 끝난 뒤 정리할 때 삭제된다.
- 즉시 삭제는 `DestroyImmediate`를 사용한다.

### **6. 유니티 물리**
#### **좌표계**
- 유니티는 왼손 좌표계를 사용한다. (X, Y, Z 좌표)
- 좌표는 보통 Vector3, Vector2 자료형으로 사용한다. (구조체이므로 값형이다.)
	- C#에서는 new를 사용한다고 힙 메모리에 저장되는 것이 아니다.
	- 참조 전달이 아닌 값 복사가 일어난다.
- Vector3는 RGB 색상에 사용하기도 한다.

#### **쿼터니언 (Quarternion)**
- **쿼터니언** : 오일러 회전의 짐벌락 현상을 방지하기 위해 나온 회전 방법
- 오일러 회전은 X, Y, Z 축이 일정 순서로 순차적으로 회전을 하기 때문에 축이 완전히 겹쳐지는 **짐벌락** 문제가 있었다.
- 쿼터니언은 X, Y, Z, W 축이 한 번에 회전을 하기 때문에 짐벌락이 없다.

#### **Input System (키 입력)**
- **Input.옵션()**메서드로 입력 가능
- 입력은 Update()에서 처리한다.

### **2. 유니티 시간**
- **Time.deltaTime** : 이전 프레임에서 다음 프레임까지 걸린 시간
	- float이기 때문에 == 연산자보다 <=, < 등의 연산자를 사용하는 것이 좋다.
	- 게임 로직은 프레임이 아닌 시간 단위로 처리한다.
	- 프레임이 높을수록 deltaTime은 작아진다.

<br/>

- **Time.timeScale** : 시간의 흐름을 관리할 수 있게 해준다.
	- 하지만 타임 스케일이 0이 되면 Update()는 멈추지 않고 FixedUpdate()는 멈춘다.
	- 따라서 타임 스케일보다는 연출의 영역에서 제어하는 것이 좋다.

### **3. 유니티 Transform**
- **Transform** : 모든 게임 오브젝트가 반드시 가지고 있는 컴포넌트 (2D는 **RectTransform**)
	- 모든 게임 오브젝트가 가지고 있다는 것은 다른 오브젝트에 transform으로 접근 가능하다는 것이다.
	- **SetParent**도 transform으로 접근할 수 있다.
	- 위치 (Position), 회전 (Rotate), 크기 (Scale)로 구성된다. (3개의 **Vector3**)
	- **World Position** : 게임 월드 그 자체를 기준으로 한 좌표
	- **Local Position** : 그 게임 오브젝트의 부모를 기준으로 한 좌표
		- 자식의 Local Scale은 가급적 (1, 1, 1)이 좋다. (대신 부모의 Scale을 바꾸자)

<br/>

- **transform.Traslate** : 게임 오브젝트가 순간적으로 이동한다.
	- 미세한 장애물은 그대로 넘어갈 수도 있으니 주의해야 한다.

<br/>

```csharp
// 순간 이동
gameObject.transform.Translate(Vector3.up * 2, Space.World);

// 지속적 이동
gameObject.transform.Translate(Vector3.forward * Time.deltaTime, Space.Self);
```

<br/>

- **transform.LookAt** : 어떤 게임 오브젝트를 바라본다.

<br/>

```csharp
gameObject.transform.LookAt(otherObject.transform);
```

<br/>

- **transform.Rotate** : 게임 오브젝트를 회전한다.
	- transform.Traslate와 마찬가지로 순간적 회전, 지속적 회전이 모두 가능하다.

<br/>

```csharp
// 순간적 회전
gameObject.transform.Rotate(Vector3.up * 90f);

// 지속적 회전
gameObject.transform.Rotate(Vector3.up * Time.deltaTime * 30);
```

### **4. Rigidbody (리지드바디)**
- **Rigidbody** : 질량을 가진 물리적 객체를 만들기 위한 컴포넌트
	- **UseGravity** : 중력 여부
	- **Drag** : 공기 저항, 회전 저항 등의 마찰과 저항력
	- **충돌 반응** : **Collider**와 결합해 다른 오브젝트와의 충돌을 관리
	- **Is Kinematic** : 물리 무시, Is Kinematic 활성화 시 중력 등의 물리 법칙을 무시
	- **Interpolate** : 프레임 간의 이동을 부드럽게 보간
	- **Constraint** : 특정 방향으로의 이동, 회전 등을 의도적으로 제한할 때 사용

<br/>

- **LinearVelocity** : 속도 대입으로 가속, 정확한 컨트롤이 필요할 때 사용한다.
- **AddForce** : 힘 전달, 질량과 저항에 따라 결과가 다르다.
	- **ForceMode** : `Force (지속적인 힘)`, `Acceleration (지속적인 가속도)`, `Impulse (순간적인 충격량)`, `VelocityChange (순간적인 속도 변화)`

<br/>

```csharp
// LinearVelocity
gameObject.linearVelocity = new Vector2(targetXVelocity, currentYVelocity);

// AddForce
gameObject.AddForce(Vector3.up * jumpPower, ForceMode.VelocityChange);
```

### **5. 충돌**
- **AABB 충돌** : Axis Aligned Bounding Box, 정렬된 축을 이용한 충돌 체크 알고리즘
	- 연산이 가볍고 빨라 유니티에서 1차 검사 용도로 사용된다.
	- 메쉬의 방향과 충돌 박스의 축이 일치하지 하지 않을 수 있다.
- **OBB 충돌** : Oriented Bounding Box, Bounding Box를 이용한 정밀한 충돌 체크 알고리즘
	- AABB보다 연산량이 많고 1차에서 걸러진 오브젝트들과의 충돌 체크에 사용된다.

<br/>

- **Collider** : 게임 오브젝트의 물리적인 형체를 정의하는 컴포넌트
	- 다른 오브젝트와의 충돌을 감지할 수 있게 해준다.
	- `Sphere` < `Capsule` < `Box` <<<< `Mesh` 순으로 콜라이더가 무거워진다.
	- `Box Collider`가 OBB 연산을 수행한다.
	- `Mesh Collider`는 매우 무겁기 때문에 지양하는 것이 좋다.

<br/>

- **Trigger** : 다른 오브젝트를 통과할 수 있으며 오로지 충돌을 감지하기만 한다.
- **Collision** : 물리적인 충돌을 감지하며 다른 오브젝트를 통과할 수 없다.
	- **Is Trigger** 체크 박스로 전환할 수 있다.

<br/>

- **Compound Collider** : **최적화**를 위해 하나의 Mesh Collider 대신 여러 개의 Sphere Collider를 사용하는 방법
	- 자식 오브젝트에 콜라이더가 많아도 반드시 Rigidbody는 부모 오브젝트에만 넣어야 한다.

### **7. 데일리 과제**
```csharp
using UnityEngine;

public class PlayerMove : MonoBehaviour
{
    public float moveSpeed = 5.0f;
    public float jumpPower = 5.0f;
    public float collideDis = 30f;
    public float angle = 5f;

    private bool _isForward = true;
    private bool _isRight = false;

    private Rigidbody _rigidbody;

    private void Start()
    {
        _rigidbody = GetComponent<Rigidbody>();
    }

    void Update()
    {
        if (Input.GetKey(KeyCode.W))
        {
            _isForward = true;
            _isRight = false;

            Move();
        }
        else if (Input.GetKey(KeyCode.S))
        {
            _isForward = false;
            _isRight = false;

            Move();
        }
        else if (Input.GetKey(KeyCode.D))
        {
            _isForward = false;
            _isRight = true;

            Move();
        }
        else if (Input.GetKey(KeyCode.A))
        {
            _isForward = true;
            _isRight = true;

            Move();
        }

        if (Input.GetKey(KeyCode.Q))
        {
            Rotation(-angle);
        }
        else if (Input.GetKey(KeyCode.E))
        {
            Rotation(angle);
        }

        if (Input.GetKeyDown(KeyCode.Space))
        {
            Jump();
        }

        Shoot();
    }

    private void Move()
    {
        Vector3 dir = Vector3.forward;

        if (_isForward && !_isRight)
        {
            dir = Vector3.forward;
        }
        else if (!_isForward && !_isRight)
        {
            dir = Vector3.back;
        }
        else if (!_isForward && _isRight)
        {
            dir = Vector3.right;
        }
        else
        {
            dir = Vector3.left;
        }

        transform.Translate(dir * Time.deltaTime * moveSpeed);
    }

    private void Rotation(float angle)
    {
        transform.Rotate(Vector3.up * angle);
    }

    private void Jump()
    {
        _rigidbody.AddForce(Vector3.up * jumpPower, ForceMode.VelocityChange);
    }

    private void Shoot()
    {
        RaycastHit hit;

        if (Physics.Raycast(transform.position, transform.forward, out hit, collideDis))
        {
            Debug.Log($"몬스터 {hit.collider.gameObject.name}이(가) Ray에 맞았습니다!");

            Destroy(hit.collider.gameObject);
        }
    }
}

```

### **2. Overlap**
- **Overlap** : 특정 영역 안에 어떤 충돌체들이 있는지 체크하는 방식
- 일시적, 즉각적인 확인이 필요한 경우에 사용한다.
- 호출할 때만 한 번 검사를 한다.
- 별도의 Collider 컴포넌트가 없어도 된다.
- 오버랩은 호출 시 새로운 배열을 생성하기 때문에 GC가 발생한다.
	- 이를 방지하기 위해 NonAlloc을 사용한다.

```csharp
Collider[] hitColliders = Physics.OverlapSphere(center, radius, layerMask);

// NonAlloc
Collider[] _overlapHit = new Collider[10];	// 이 배열을 재사용
Physics.OverlapSphereNonAlloc(center, radius, _overlapHit, layerMask);
```

### **3. RaycastAll**
- **RaycastAll** : Raycast와 달리 레이저를 맞는 대상을 배열로 받아온다.
- 일반 Raycast와 달리 RaycastAll은 오브젝트를 관통해서 사거리 안에 있는 대상들을 감지한다.
- Raycast에서 레이저의 위치를 바꿀 때 게임 오브젝트 안에 Raycast를 위한 새로운 오브젝트를 만드는 것이 좋다.

	- 별로 좋은 방식은 아니다.

```csharp
using UnityEngine;

public class EnemySpawner : MonoBehaviour
{
    public GameObject monsterPrefab;
    public Transform margin1;
    public Transform margin2;
    public GameObject monsterParent;

    void Awake()
    {
        float minX = margin1.position.x;
        float maxX = margin2.position.x;
        float minZ = margin1.position.z;
        float maxZ = margin2.position.z;

        for (int i = 0; i < 10; i++)
        {
            float randomX = Random.Range(minX, maxX);
            float randomZ = Random.Range(minZ, maxZ);

            Instantiate(monsterPrefab, new Vector3(randomX, 1, randomZ), gameObject.transform.rotation, monsterParent.transform);
        }
    }
}
```

```csharp
using UnityEngine;

public class Enemy : MonoBehaviour
{
    public float enemySpeed = 10f;

    private GameObject player;
    private Rigidbody rb;

    void Awake()
    {
        player = GameObject.Find("Player");

        rb = GetComponent<Rigidbody>();
    }

    void Update()
    {
        gameObject.transform.LookAt(player.transform.position);

        FollowPlayer();
    }

    private void FollowPlayer()
    {
        // Translate : 회전(LookAt)과 이동이 따로 진행
        // 적 오브젝트들이 회오리 치듯이 밀리고 모인다.
        //gameObject.transform.Translate(player.transform.position * Time.deltaTime * enemySpeed);

        // 플레이어와 적 오브젝트 사이의 거리를 구한다.
        // 제미나이 : 단순히 거리의 차이만 구하면 안됨
        // 벡터의 방향만 필요하기에 크기를 1로 정규화해야 한다. (.normalized가 이를 정규화한다.)
        Vector3 dir = (player.transform.position - gameObject.transform.position).normalized;

        rb.linearVelocity = dir * enemySpeed;
    }
}
```

### **1. GPU와 CPU**
- **GPU**는 CPU와 달리 **대규모 병렬 처리**가 가능하다.
- 따라서 한 번에 많은 픽셀을 동시에 그릴 수 있다.
- **드로우 콜**이란 어떤 리소스를 어떻게 그릴지 명령하는 것을 의미한다. 즉, 이미지나 텍스쳐 등을 한 번 전달할 때마다 드로우콜이 발생한다.
- 이 드로우 콜을 줄이기 위해 여러 개의 명령을 묶어서 전달하는 **Batching**을 한다.
- 유니티에서 캔버스를 그리면 최소 한 번의 드로우 콜이 필요하기에 캔버스 안에서 캔버스를 불러오는 것은 지양해야 한다.
